PM99 No-CD: Three Bytes, One Gate

This started as a simple question: "What did the crack really change?" The answer turned out to be cleaner and more interesting than expected.

Target: MANAGPRE.EXE Protection: DISK.ID token check Patch style: tiny in-place edits

The crack does not delete protection logic wholesale. It does something subtler: it moves the lookup path from CD-centric behavior toward local-relative behavior, and removes one CD-ROM branch gate.

The Story in One Minute

Original PM99 startup searches drives, treats CD-ROM as special, reads DISK.ID, and compares 7 bytes against built-in tokens. If this chain fails, you get the familiar message:

"THE GAME CAN'T BE STARTED"
You need the original PREMIER MANAGER 99 CDROM in your CD drive"

The patched executable still expects DISK.ID, but it no longer relies on the same CD-only path/gate sequence.

What We Actually Verified

On Disc

disk.id exists and is 7 bytes: 50 43 50 36 20 30 30 which is PCP6 00.

In Binary

Static token strings include PFR5 00, PCA5 00, PCC6 00, PCP6 00, PCF6 00.

In Practice

When local DISK.ID is renamed, startup fails. So validation still exists after patching.

Before and After, Visually

The Three Edits

Address Before After Meaning in Plain English
0x00408CF6 8A 44 24 10 66 B8 2E 00 Stop taking a runtime byte for path seed; force '.' instead.
0x00408D19 75 12 90 90 Remove one CD-ROM-dependent conditional jump.
0x0072C77D (data) 3A 5C 5C 00 Tweak embedded path template bytes so :\ behavior shifts toward local-relative format.

High-Level Model (Readable, Not Reconstructed)

// before
for each drive:
    if drive_type != CDROM: continue
    if read7(drive + "\\DISK.ID") matches expected_token:
        launch_game()
show_insert_original_cd_message()

// after (conceptually)
if read7(".\\DISK.ID") matches expected_token:
    launch_game()
else:
    // remaining path logic still exists, but one strict CD branch is gone
    follow_relaxed_lookup_path()
Reality check: if you rename local DISK.ID, patched startup fails. That is the strongest practical proof that this is a reroute patch, not a full check removal.

So What Was the Crack, Exactly?

Not a giant crack intro. Not a packed stub. Not a replacement loader.

It is a surgical retargeting of path logic and branch behavior: the executable is nudged away from "must be CD device path" and toward "accept local marker path first," while still relying on token comparison.
