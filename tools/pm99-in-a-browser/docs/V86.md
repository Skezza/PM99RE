# V86 Browser Backend

## Purpose

The v86 path tests PM99 inside a full x86 PC emulator in the browser. The guest
owns Windows compatibility, DirectDraw state, registry entries, and PM99 install
layout. The host page only supplies local runtime artifacts and controls the
emulator lifecycle.

This is separate from any future BoxedWine path. BoxedWine would target a
Wine-style userspace runtime for the Windows executable; this scaffold is the
full-machine v86 backend.

## Current Scaffold

Path: `tools/pm99-in-a-browser/v86/`

- `index.html`: static launcher UI served over HTTP.
- `js/v86-launcher.js`: zero-dependency module that loads local `libv86.js`,
  creates `V86`/`V86Starter`, attaches screen/status listeners, saves/restores
  state, and swaps CD-ROM media from a local file input.
- `configs/windows98-pm99.json`: hard-disk-first Windows 98 profile.
- `configs/windows2000-pm99.json`: hard-disk-first Windows 2000 profile.
- `assets/` and `vendor/`: documented local-only drop zones with ignore rules.

No proprietary Windows/PM99 media and no downloaded v86 build artifacts are
tracked.

## Required Local Artifacts

```text
tools/pm99-in-a-browser/v86/vendor/libv86.js
tools/pm99-in-a-browser/v86/vendor/v86.wasm
tools/pm99-in-a-browser/v86/assets/bios/seabios.bin
tools/pm99-in-a-browser/v86/assets/bios/vgabios.bin
tools/pm99-in-a-browser/v86/assets/disks/win98-pm99.img
tools/pm99-in-a-browser/v86/assets/disks/win2000-pm99.img
tools/pm99-in-a-browser/v86/assets/media/pm99.iso
```

The filenames are examples. If local names differ, update the matching JSON
profile. PM99RE must not track any of these payloads.

## Run Locally

```sh
cd tools/pm99-in-a-browser/v86
python3 -m http.server 8765
```

Then open `http://127.0.0.1:8765/`.

The page should report missing assets cleanly if the local runtime files are not
present. Do not run it through `file://`; v86 fetches ROMs and images through
browser request APIs.

## Guest Image Assumptions

- Windows is already installed to the hard disk image referenced by `hda`.
- PM99 is installed in the guest or available from the mounted CD-ROM image.
- Windows 98 is the first target because it is closer to PM99's original era.
- Windows 2000 is useful for comparison, but should be installed/configured as
  Standard PC rather than ACPI PC for v86 compatibility.
- DirectDraw behavior still needs empirical validation in the guest. If PM99
  reaches menus but fails on match rendering, capture guest display mode,
  DirectX version, and any PM99 compatibility patches used.

## Config Notes

The `v86` object in each JSON file is passed to the v86 constructor after the
launcher injects the screen container and converts named boot orders to numeric
values.

Useful boot orders:

- `HARDDISK_CD_FLOPPY`: normal PM99 run after Windows is installed.
- `CD_HARDDISK_FLOPPY`: OS installer or recovery media first.
- `FLOPPY_HARDDISK_CD`: DOS/utility floppy first.

For large disk images, switch an image object to async loading and include its
exact byte size:

```json
{
  "url": "assets/disks/win98-pm99.img",
  "async": true,
  "size": 2147483648
}
```
